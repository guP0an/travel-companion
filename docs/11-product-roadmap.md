# 11 · 丸玩完整产品路线图

> 状态：当前有效  
> 最近更新：2026-07-14  
> 用途：统一记录丸玩尚未实现的完整产品规划。RAG 只是其中一条能力线，不代表全部未来范围。

## 1. 产品终局

丸玩不是一次性生成行程的页面，而是一款覆盖旅行全周期的手机优先产品：

```text
行前：AI 规划 + 票据整理 + 同行协作
行中：地图总览 + 路线调整 + 语音随行 + 周边发现 + 账本
行后：游记 + 个人记忆地图 + 偏好沉淀
长期：好友社交 + 旅行圈子 + 真实内容网络
```

最终形成的飞轮是：规划产生行程，行程产生打卡和内容，内容点亮地图并形成记忆，记忆改善下一次规划，优质内容再进入社交与圈子。

## 2. 七条产品能力线

| 能力线 | 核心能力 | 当前状态 |
|---|---|---|
| AI 旅行管家 | 提问引导、截图识别、行程生成与调整、事实核验 | Phase 1 已有主体，仍需打磨 |
| 记忆与 RAG | 稳定偏好、历史反馈、个人记忆检索、公共旅行知识检索 | 尚未实现 |
| 地图体系 | 行程地图汇总、行中实时地图、个人记忆地图、社交地图 | 只有单地点地图入口和服务端核验 |
| 语音随行陪伴 | 实时对话、可信指路、主动提醒、位置与行程上下文建议 | 尚未实现 |
| 同行与社交 | 分享、同行人协作、关注/好友、动态、互动 | 尚未实现 |
| 圈子与内容 | 城市圈、主题圈、问答、攻略、推荐/踩坑、内容治理 | 尚未实现 |
| 旅行沉淀 | 游记、照片、账本、打卡、成长、年度回顾 | 已有账本/打卡/成长地基，尚未形成完整回忆产品 |

## 3. 地图不是一个功能

丸玩规划中的“地图”分为四种，不能混写：

### 3.1 行程地图汇总

把当前行程全部地点放在一张地图上，按天使用不同颜色或编号展示。

- 地图/清单双向联动；
- 按天筛选，显示当天路线和顺序；
- 点击标记查看时间、停留时长、丸玩提醒；
- 标出无法定位、距离异常和路线折返；
- 支持把地图版行程分享给同行人。

这是最接近当前规划流程、应最先实现的地图能力。

### 3.2 行中实时地图

基于当前位置显示下一站、交通方式、预计时间和附近推荐。需要定位授权、路线 API 和更稳定的移动端载体。

### 3.3 个人记忆地图

按真实打卡点亮去过的省、市和景点，关联当时的行程、照片、账本与游记。即使没有其他用户，单人版本也能成立。

### 3.4 社交地图

在用户主动公开和隐私可控的前提下，展示朋友或圈子成员去过的地方、公开内容和真实评价。它依赖用户量、内容治理和个人记忆地图，不应先于单人版本上线。

## 4. 语音随行陪伴

“丸玩随行”不是把文字答案念出来，而是旅行中的实时管家：

- 用户可按住说话或唤醒丸玩，连续追问“下一站怎么走”“附近吃什么”“要不要提前回酒店”；
- 丸玩读取用户授权后的当前位置、当前时间、当天行程、票据、天气和官方预警；
- 指路信息必须来自地图路线/导航 API，丸玩只负责用自然语言解释，不自行编造转弯和距离；
- 到站、临近预约、天气突变、路线延误或附近有合适地点时，主动给出简短建议；
- 提供“安静 / 简洁导航 / 陪伴聊天”模式，避免持续打扰；
- 支持暂停收音、关闭定位、删除语音记录，并明确显示麦克风与定位状态；
- 不默认保存原始录音，只沉淀用户主动确认的偏好或旅行记忆。

第一阶段可在手机网页实现按住说话、语音转文字和前台对话；可靠的锁屏/后台随行、持续定位、导航播报和低延迟打断更适合小程序或原生 App。

## 5. 同行社交与旅行圈子

### 5.1 同行与好友社交

- 邀请同行人查看或共同编辑一份行程；
- 行程内投票、备注和分工；
- 关注/好友关系与个人旅行主页；
- 发布公开或仅好友可见的旅行动态；
- 对游记、打卡和路线点赞、收藏、评论；
- 清晰的公开范围、拉黑、举报和删除能力。

第一步应从“围绕一趟具体旅行协作”开始，而不是先做空的聊天广场。

### 5.2 旅行圈子

圈子是围绕目的地或兴趣形成的内容社区，与好友关系不同。

- 城市圈：如“武汉周末”“京都自由行”；
- 主题圈：如“亲子旅行”“带父母出游”“徒步”“美食”；
- 圈内问答、短帖、游记、路线和推荐/踩坑；
- 优质内容可被丸玩检索，但必须标明来源和时效；
- 圈主/管理员、内容审核、举报、反广告和隐私机制。

圈子冷启动时先使用现有真实打卡、游记和公开路线填充内容，不制造虚假用户或虚假帖子。

## 6. 分阶段路线图

### M0 · 内测稳定闭环（当前）

- 跑通登录、识图、生成、修改、收藏、账本、打卡；
- 完成账本私有凭证数据库迁移；
- 配齐天气预警与地图事实凭据；
- 做真实用户冒烟、错误监控和持久化限流。
- 完成小程序工程地基、微信登录、正式域名和真机登录验收。

### M1 · 会问、会记的丸玩

- 生成前 2–4 个必要追问；
- 保存可查看、修改、删除的稳定偏好；
- 用历史选择和反馈改善下一次规划；
- 建立 RAG 检索、冲突优先级、来源和评测。

### M2 · 行程地图与同行协作

- 上线行程地图汇总、按天路线和清单联动；
- 对距离异常、折返和无法定位给出提示；
- 分享只读行程，邀请同行人参与编辑、备注和投票；
- 行中提供下一站和轻量周边发现；
- 上线前台按住说话、语音问答和可信路线播报的“随行轻量版”。

### M3 · 旅行回忆、个人地图与随行完整版

- 打卡自动汇总为游记草稿；
- 照片、账本、路线和点评形成一趟旅行档案；
- 点亮个人省/市/景点记忆地图；
- 生成月度/年度旅行回顾，并反哺个人记忆；
- 在合适载体上实现可打断对话、主动提醒、持续定位与后台运行的“丸玩随行完整版”。

### M4 · 好友社交与旅行圈子

- 个人主页、关注/好友、动态和互动；
- 城市圈与主题圈；
- 公开路线、游记、推荐/踩坑的搜索与收藏；
- 完整上线内容审核、举报、拉黑、隐私和反滥用体系；
- 在用户授权与来源透明的前提下，把优质公开内容纳入公共 RAG。

### M5 · 商业化与生态

- 会员能力：更强记忆、协作人数、地图与回顾能力；
- 合规的票务/酒店/门票跳转或佣金合作；
- 本地创作者路线和圈子运营工具；
- 不以广告干扰规划结果，不让商业排序覆盖用户利益。

## 7. 优先级原则

1. 先解决一个人的真实旅行，再解决多人网络效应。
2. 行程地图汇总早于社交地图，同行协作早于陌生人广场。
3. 个人记忆早于公共知识库，真实打卡早于内容扩张。
4. 社交和圈子必须与审核、举报、隐私一起设计。
5. 每个阶段都要验证留存、复用和真实旅行价值，不按页面数量判断进度。

- 行程地点一图汇总和路线联动；
- 行中实时地图与周边推荐；
- 语音对话、可信导航播报与实时随行陪伴；
- 同行人邀请、共同编辑、投票和备注；
- 游记自动整理与旅行档案；
- 个人记忆地图；
- 好友/关注、动态与互动；
- 城市圈、主题圈和圈内问答；
- 社交地图和公开内容 RAG；
- 内容审核、举报、拉黑与隐私控制；
- 会员和合规商业化。
