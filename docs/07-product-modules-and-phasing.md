# 07 · 产品模块与分期

> 状态：执行中 · 最近同步 2026-07-10 · 决策人：lord
> 本文定义产品的完整模块组成，以及为解开「社交冷启动死结」而设计的分期上线策略。

---

## 1. 三大模块（完整愿景）

| 模块 | 描述 | 本质 | 单人是否成立 |
|------|------|------|--------------|
| **① 行程规划** | 用户提供时间/地点/预算等 → **以「提问引导式」为主**（像管家聊天一步步问），AI 生成带性格的每日行程 | 工具内核 | ✅ 成立 |
| **② 同行社交 / 好友 / 圈子** | 同行协作、好友动态，以及按城市或兴趣组织的内容圈子 | 协作 + UGC 社交 | ❌ 需真实内容和治理能力 |
| **③ 中国地图** | 中国地图，可缩放，查看省/市的特色；用户到过的地方浮现其**头像气泡** | 记忆可视化 + 社交 | ⚠️ 见下 |

### 已定决策
- **① 输入方式**：以**提问引导式**为主（form 手填作为后续补充，非 MVP）。理由：最贴合「温柔贴心管家」人设，对话感强。

---

## 2. 关键产品判断（为什么不能三个一起上）

### 判断一：只有 ① 单人就有价值，②③ 有「冷启动死结」
新产品最容易死在「社交功能上线即空城」——论坛没人发帖是空的，地图上没别人的气泡也是空的。若三个一起上，用户打开看到的是一座空城，自己都没动力维护。

### 判断二：地图是产品灵魂，且能「单人先跑」
「到过的地方浮现头像气泡」与 lord 一贯的执念——**记忆 / 走过的痕迹 / 被记住**——是同一个东西。
所以地图首先应做成**「你自己的旅行记忆地图」**：你去过哪，地图就点亮哪，配上当时的行程/照片。**这个版本不需要任何其他用户就成立**，单人就很动人；等有了用户，再让「别人的头像气泡」浮上来，自然进化成社交。

> 这一步把冷启动死结解开了：**地图先做单人记忆地图，社交是它后来的升级，不是前提。**

### 判断三：数据依赖关系 ① → ② → ③
地图上的「到过 / 特色 / 气泡」数据，来源于用户的行程记录与上传内容。
因此数据流与开发顺序都应是 ①（产生行程）→ ②（产生 UGC/打卡）→ ③（聚合可视化）。

---

## 3. 分期上线策略

```
Phase 1a（已完成）  可运行功能原型
                    真生成 / 修改 / 收藏 / OCR / 天气 / 账本 / 打卡 / 导出

Phase 1b（当前）    内测闭环：会问、会记、能安全上线
                    目标：给 5–10 位真实用户使用，验证「可用、想转发、回头」

Phase 2（未开始）   ③ 个人记忆地图 + 游记
                    已有打卡/照片/成长作为数据地基，但地图与游记尚未开发

Phase 3（未开始）   ② 好友社交 / 城市圈 / 主题圈 + ③ 社交地图
                    目标：有用户基数后形成网络效应与护城河
```

---

## 4. 各模块技术要点（初步，待 ③a 架构文档细化）

- **① 行程规划**：提问引导式对话 → 结构化收集（目的地/天数/预算/脾气）→ 经 serverless 代理调 DeepSeek API → 返回行程 JSON → 渲染。
- **② 论坛/朋友圈**：需要真正的后端 + 数据库 + 用户账号 + 图片存储（对象存储）+ 内容审核。**比 ① 重得多**，故置于 Phase 3。
- **③ 地图**：中国地图可缩放、省/市下钻。技术候选：高德/百度地图 SDK（真实地理）或 ECharts 中国地图（风格化）。气泡 = 自定义 marker。Phase 2 单人版只需本地/轻后端记录「去过的城市」。

---

## 5. 对 MVP（Phase 1）范围的影响

- 当前已有打卡、照片和成长能力，但它们只作为未来记忆地图的数据地基，不代表 Phase 2 已上线。
- Phase 1b 只补齐提问引导、偏好记忆、模型稳定性、安全发布和真实用户验证。
- 记忆地图、游记、论坛、实时导航和语音继续留在 Phase 2/3，不挤进当前里程碑。
- 防范围爆炸的纪律不变：先证明 ① 行程规划有人爱用、愿转发、会回来。

> 📌 模块是「能力块」，还有一条「时间轴」视角——**行前 / 行中 / 行后**全周期，以及由此构成的记忆飞轮与护城河，见 [08 旅行全周期与护城河](08-travel-lifecycle-and-moat.md)。三大模块各自服务生命周期的不同阶段。

## 6. 下一目标验收条件

Phase 1b 以“可邀请真实用户内测”为完成标准：

1. 生成前完成 2–4 轮必要追问，并允许跳过。
2. 用户稳定偏好可保存，并在下一次规划时自动复用。
3. 模型输出有 schema 校验、重试和可理解的失败提示。
4. 正式网址完成登录 → 生成 → 修改 → 收藏 → 导出 → 打卡冒烟测试。
5. `/api/ai` 有登录校验或限流，旧 DeepSeek Key 已轮换。
6. 至少 5 位真实用户完成一次规划并留下反馈。
