# AI 旅行管家（旅伴）· 项目文档总览

## 一句话

一个**陪你走完每一程、还记得你走过哪儿**的 AI 旅行管家——**行前帮你排，行中陪你走，行后替你记**。
有性格（管家「丸丸」，用 lord 本人的声音）、懂你脾气、记得你。

## 我们和「直接问 AI」的区别（护城河）

通用 AI 是**一个瞬间**（行前问一下就走，不记得你）；我们是**一段关系**（陪完整程 + 把每趟旅行沉淀成记忆）。差异建在四层：**成品化 · 陪伴 · 记忆 · 社交**。完整论证见 [08](08-travel-lifecycle-and-moat.md)。

## 三大模块 × 旅行全周期

| 模块（能力块） | 生命周期（时间轴） | Phase |
|----------------|--------------------|-------|
| ① 行程规划（提问引导式管家） | 行前 · 规划 | **Phase 1（当前）** |
| ③ 中国记忆地图 + 游记 | 行后 · 记忆 | Phase 2 |
| ①延伸 + 实时地图/周边 + 语音陪伴 | 行中 · 陪伴 | Phase 2 起 |
| ② 论坛/朋友圈（社交） | 行后 → 社交 | Phase 3 |

> 飞轮：行中打卡 → 行后游记+点亮地图+反哺偏好 → 管家更懂你+喂养社交 → 行前更准。越转越强、别人复制不了。

## 关键决策（已拍板）

- **技术栈**：React + Vite + TS + Tailwind；前端 → serverless 代理藏 Key → LLM。
- **模型供应商**：**DeepSeek（永久）**，OpenAI 兼容，`deepseek-chat`。当前用 `response_format: json_object` + prompt 描述结构约束输出；运行时 schema 校验列入下一里程碑。
- **导出带图**：当前结果页可导出竖版分享卡（PNG）；PDF 暂缓。配图走真实图库/POI，**不用 AI 生成、不爬小红书**。
- **声音**：管家用 **lord 本人音色克隆**（本人授权）。Phase 2/3、需小程序/App。
- **MVP 纪律**：Phase 1 只交付「行前 ①」并打磨到有灵魂，不范围爆炸。

> 原则：**静态品牌素材**（图标/头像/吉祥物）放 `public/`；**带主题色、需明暗适配的 UI 图标**做成 `Icons.tsx` 组件；**用户产生的内容**（照片）放 Supabase Storage。

## 当前进度（2026-07-14）

**阶段判断**：Phase 1 的可演示功能原型已成型，当前进入“内测闭环 + 正式发布”阶段。

**已实现**：
- 手机优先工作台：移动端以规划输入为第一任务，生成后自动进入结果；提供日期快捷导航和底部“调整行程 / 保存图片”操作。桌面端扩展为规划台与行程稿双栏，不改变手机主流程。
- 行程生成与调整：DeepSeek 真生成、一句话修改、手动增删改、行前准备与当季限定。
- 真实信息辅助：Open-Meteo 天气前置到生成流程；可选高德 POI/同日相邻路线核验；可选和风天气官方灾害预警会直接约束行程；特殊景观概率提示、景点高德入口、当前位置显示。
- 预订信息：票务/酒店截图优先由 Kimi K2.6 直接识图，失败时回退 Tesseract OCR → DeepSeek；结果可编辑并纳入排程，带价格时可自动记账，原图不落库。
- 账号与数据：Supabase 邮箱登录；手机号验证码/手机号密码前端流程及腾讯云 Send SMS Hook 已完成，短信资质与供应商配置完成后自动开放；行程收藏、消费账本、景点打卡、评分、推荐/踩坑点评、照片云存储。
- 品牌与增长：丸丸吉祥物、按真实打卡数成长、PNG 分享卡导出。
- 页面层级：登录与注册收进顶部账户面板，不再占据规划首屏；示例行程与用户生成结果有明确状态区分。
- 部署基础：Vite 静态前端 + Vercel `api/ai.ts` serverless 入口，项目已关联 Vercel。

**已验证**：
- 前端与 Node 端 TypeScript 检查通过。
- Vite 生产构建通过（124 个模块）。
- 本地 5 个必需环境变量已配置，`.env.local` 未被 Git 跟踪。
- Vercel Production 已切换到有效的 `travel-wanwan` Supabase 项目；线上站点、认证健康检查和登录错误响应均已验证。
- 密码找回流程、AI 接口登录鉴权、每用户基础限流、请求边界校验和友好错误降级已完成。
- 模型返回已增加运行时行程结构校验；`pnpm test` 覆盖令牌、限流、请求参数、行程结构、Kimi 多模态请求与图片边界、天气与灾害预警、高德事实解析、票据脱敏、手机号规范化、短信 Hook 安全校验和 Supabase 迁移契约，共 18 项。
- 有出发日期时，服务端会在生成前查询天气并作为事实交给 DeepSeek；配置 `AMAP_WEB_SERVICE_KEY` 后会核验 POI 和相邻路线，发现未核验地点或超长步行时触发局部修复。
- 配置和风天气后，系统只在临近出发时查询当前生效官方预警；严重预警会持久化到行程、在页面顶部展示，并要求 DeepSeek 改为安全安排。
- 票据 OCR 文本在发送模型前会隐藏姓名、手机号、邮箱和证件号，结构化结果不再保留订单号等无关个人信息。
- 云端实测：`profiles`、`itineraries`、`expenses`、`checkins` 四张表与 `checkin-photos`、`expense-receipts` 存储桶已部署；建表、触发器和 RLS 已同步到新生产项目。
- Supabase Site URL 已指向正式站点，密码重置 `/?reset=1` 回跳已加入允许列表。

**当前缺口**：
- 手机验证码、手机密码注册/登录、找回密码及 Send SMS Hook 已完成，但 Supabase Production 的 Phone Provider 尚未启用；需完成企业短信资质、签名/模板审核、供应商参数和防刷配置后开放。
- 官方灾害预警代码已完成；线上启用仍需在 Vercel 配置和风天气专属 API Host 与 API Key。
- 规划入口仍是“一段话直接生成”，尚未实现 PRD 中的 2–4 轮提问引导。
- 历史行程与打卡数据尚未反哺用户偏好，真正的“越用越懂你”未闭环。
- Kimi 识图代码、Key 与 Production 部署已完成，仍需登录后上传真实票务截图完成最终冒烟。
- 模型结果已有运行时结构校验、友好降级和基于地图问题的条件式修复；普通格式错误尚未增加通用自动重试。
- 当前限流是单个 serverless 实例内的基础保护；扩大内测前应接持久化限流，并轮换 DeepSeek Key。
- 行程地图汇总、同行协作、记忆地图、游记、好友社交、城市/主题圈子和语音尚未实现，完整范围与先后关系见 11。

## 下一目标：Phase 1 内测闭环

让丸丸做到**会问、会记、能安全上线**：

1. 用真实账号完成登录 → 找回密码 → 生成 → 收藏 → 账本 → 打卡的用户态线上冒烟测试。
2. 生成前完成 2–4 轮必要追问，同时允许用户跳过。
3. 保存并复用预算、同行人、兴趣、避雷等稳定偏好。
4. 在现有结构校验和温柔降级上增加一次自动修复/重试。
5. 把 `/api/ai` 基础限流升级为持久化限流，并轮换旧 Key。
6. 邀请 5–10 位真实用户完成一次规划，记录“可用 / 想转发 / 回头”三项信号。

> 在上述目标验收前，不启动记忆地图、论坛或语音开发。
