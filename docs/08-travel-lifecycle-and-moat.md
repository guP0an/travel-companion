# 08 · 旅行全周期与护城河（行前 · 行中 · 行后）

> 状态：草稿 · 2026-06-13 · 作者：赛巴斯蒂安 + lord
> 回答两个根本问题：① 我们和「直接问 AI」到底有什么区别？② 为什么不能只管行前、还要管行中行后？
> 关联：[07 模块分期](07-product-modules-and-phasing.md)、[02 竞品](02-competitive-analysis.md)、[PRD](PRD-v0.1.md)。

## 1. 根本差异：一次性 AI 只管「行前一问」，我们陪完整程

**残酷的实话**：如果只是「聊天框 → 吐一段文字」，和直接问 DeepSeek/豆包没区别，套壳必死。差异不能建在「会生成行程」上，要建在通用 AI 给不了的东西上：

| 层 | 通用 AI | 我们 |
|----|---------|------|
| 成品化 | 一坨文字，自己整理 | 排好版、可导出图片/PDF 的成品 |
| **陪伴** | **一次性，问完即走** | **行前→行中→行后全程在场** |
| 记忆 | 对话即焚，不记得你 | 沉淀历史、越用越懂你、点亮你走过的地方 |
| 社交 | 永远单机 | 别人的真实痕迹，网络效应 |

> **核心洞察**：通用 AI 是**一个瞬间**（行前问一下）；我们是**一段关系**（陪你走完、记住你）。这正好长在 lord 的 IP 内核——「记忆 / 被记住 / 一个懂你的存在」——上。

## 2. 三段式旅行生命周期

### 🧭 行前 · Plan（已是 ① 行程规划核心）
- 提问引导式生成带性格的行程（[05](05-butler-prompt-design.md)/[06](06-butler-questions.md)）。
- 导出竖版**分享卡 / PDF**：揣兜里、发同行群、晒社交（兼增长钩子）。
- 行李 / 天气 / 订位 / 门票提示。
- **城际交通建议**：出行日的航班 / 高铁 / 火车票班次建议（去程/返程、多城之间）。MVP 先给建议（班次/时段/约时长），真实余票与价格属后续接票务/聚合 API（12306 无对外开放 API、机票走聚合商，涉成本与合规）。
- **上传票务截图自动解析（懒得打字）**：用户传 12306 / 机票截图 → 自动读出班次/到达时间/日期 → 丸玩据此排程。DeepSeek 文本模型看不了图，方案=**OCR 先行**（国内 OCR 抽文字→喂 DeepSeek，推荐）或国产多模态看图提取。需接 OCR 服务，归 Phase 2。

### 🚶 行中 · Travel（新增重点——通用 AI 完全缺位的战场）
| 功能 | 为什么通用 AI 做不到 |
|------|----------------------|
| **行程随身**：今天去哪、按时段卡片，导出后离线也能看 | 它不知道「你此刻在路上」 |
| **实时地图 + 周边推荐**：到了一处景点，自动搜罗附近的美食 / 好玩的，按你口味用管家口吻推 | 它不知道「你现在站在哪」 |
| **语音实时陪伴**：管家用声音陪你走，边走边能问能答（声音先用 lord 本人音色克隆） | 它没有「边走边说、声音熟悉」的在场感 |
| **临场实时调整**：下雨了/景点关门/走累了 → 管家改今天剩下的安排 | 它不知道你刚出了状况，也不记得原计划 |
| **即时贴心提醒**：基于时间/位置（11 点前到避队、天黑前回、末班车） | 它没有「现在几点、你在哪」的上下文 |
| **随手打卡**：拍照、记一句心情 | —— 这些沉淀直接喂给「行后」与记忆地图 |

> 管家从「攻略生成器」变成「身边的旅伴」——有声音、知道你在哪、能随时给附近的建议。这一段是和纯 AI 拉开差距最狠的地方。

#### 行中这层的技术与平台现实（务实，避免画饼）
- **地图 + 周边推荐**：用高德/百度地图 SDK + POI 周边搜索（可商用授权，有美食/景点/评分/营业时间）。需用户授权**定位权限**。
  - ⚠️ 此处的「地图」是**行中实时定位地图（工具属性）**，与 ③ 模块的「行后记忆地图（点亮痕迹、情感属性）」是两种用途、共用同一套地图 SDK。
- **语音**：管家说话 = TTS（文字转语音）；用户说话 = ASR（语音识别）；实时陪伴 = 双向打通。
- **声音用 lord 本人**：做音色克隆，最贴「丸玩」管家人格——管家用您的声音说话。
  - ✅ 是您本人声音、您本人授权，没有第三方肖像/声音问题。
  - ⚠️ 声音克隆模型是**敏感资产**，须妥善保管、不外泄；若将来面向公众规模化，再评估是否继续用真人声或换合成音。
- **平台现实**：实时定位 + 麦克风 + 常驻陪伴，基本是**小程序 / App 的活**，纯 H5 网页体验受限。这正好对齐 PRD「验证 OK 再上小程序」——**行中实时陪伴是上小程序后的杀手锏**，不强塞进 Phase1 网页原型。
- **分期**：以上归 **Phase 2 / 3 的行中**，Phase 1 不做（守纪律见 §4）。

### 📖 行后 · Remember（新增重点——记忆飞轮的起点）
| 功能 | 价值 |
|------|------|
| **一键生成游记/回忆卡**：行中的照片+足迹+行程 → 管家口吻的精美游记，可导出可分享 | 又一个增长钩子；把「一次旅行」变成「一份能晒的作品」 |
| **点亮记忆地图**：这趟去过的城市/省份点亮（③ 模块） | 「你的旅行痕迹」——最动人的留存钩子 |
| **反哺偏好**：你这趟实际爱去/避开了啥 → 管家更懂你 | 「越用越准」的数据飞轮 |
| **沉淀为 UGC**：把回忆发出去 → 给别人当攻略（② 论坛） | 喂养 Phase3 社交与专属攻略库 |

## 3. 飞轮：三段不是并列，是一个闭环

```
        行前 Plan ──────────────┐
        生成行程 / 导出分享卡      │
            │                    │  下次更准、可复用
            ▼                    │  别人可参考
        行中 Travel              │
        随身看 / 临场调整 / 打卡   │
            │                    │
            ▼                    │
        行后 Remember ───────────┘
        游记 + 点亮地图 + 反哺偏好 + 沉淀 UGC
```

- **留存引擎**：单次 AI 用完就走；这个闭环让用户一趟接一趟回来。
- **数据飞轮**：行中打卡 → 行后沉淀 → 管家更懂你 + 喂养社交地图 → 行前更准。越转越强，**别人无法复制**（它长在用户自己的旅行记忆上）。

## 4. 与模块 / 分期对齐（守住 MVP 纪律，别范围爆炸）

生命周期是「时间轴」，三大模块是「能力块」，对应关系：

| 生命周期 | 主要靠哪个模块 | 落在哪个 Phase |
|----------|----------------|----------------|
| 行前 Plan | ① 行程规划 | **Phase 1** |
| 行后 Remember | ③ 记忆地图 + 游记 | Phase 2 |
| 行中 Travel | ① 延伸 + 实时地图/周边 + 语音陪伴（需小程序/App、定位、麦克风） | Phase 2 起 |
| 行后→社交 | ② 论坛 + ③ 升级为社交地图 | Phase 3 |

**纪律不变**（对齐 [07](07-product-modules-and-phasing.md)、[PRD §3](PRD-v0.1.md)）：
- **Phase 1 仍只交付「行前 ①」并打磨到有灵魂**——导出分享卡同时服务行前晒图与行中随身看，是 Phase1 内的高性价比一环。
- 行中、行后正式进入**产品愿景与路线图**，但不挤进 Phase1 开发。先把行前做到「有人爱用、愿转发」，再顺着飞轮往行中、行后长。

## 5. 一句话定位升级

> 旧：一个帮你排好行程的 AI 旅行管家。
> **新：一个陪你走完每一程、还记得你走过哪儿的旅行管家——行前帮你排，行中陪你走，行后替你记。**

这句话里，「陪你走、记得你」就是通用 AI 永远说不出口的那部分。

## 6. 产品进化：旅行 + 账本 + 丸玩养成（飞轮再加固，2026-06-13 lord 提）

把丸玩从"行程工具"升级成 **「游玩 + 账本 + 养成」三合一**。三者不是堆功能，而是喂同一个数据飞轮：

### 6.1 丸玩成长线（养成 / 情感留存）
- 丸玩**随出行次数（或去过的城市数）成长**：初级 → 进阶 → 高级形象，越玩越"高级"。
- 当前 `src/components/Mascot.tsx` 是**初级形象**（小丸子）；后续按等级出更精致/带装备的形象（戴帽、背包、解锁配色等）。
- 价值：把"被记住 / 陪伴"做成**看得见的养成**，是最强留存与情感钩子，正好长在 lord 的 IP 内核上，通用 AI 给不了。
- **已做（2026-06-13）**：等级口径=**只认真实打卡数**（不认收藏、不认生成行程），逻辑在 `src/lib/growth.ts`（6 档：初心丸子/小小旅人/识途丸子/老练旅人/风物丸子/行脚僧）。头像旁显示 `Lv.X · 称号 · 打卡 N 处 · 再打卡 M 处升级`。打卡里程碑徽章（常客/本地通/资深旅人/风物志）在打卡面板显示。**待做**：按等级换更精致的丸玩形象。

### 6.2 账本 / 消费记录（游玩+账本集合）
- 记录旅途各种**消费**（餐饮/交通/门票/住宿/购物…），按行程归集，行后看一趟花了多少。
- 数据：新表 `expenses`（user_id, itinerary_id?, category, amount, note, spent_at），RLS 同 itineraries。
- 归属：**行中**随手记 + **行后**复盘。让产品从"看一眼的行程"变成"一趟旅行的完整账"。
- **票据自动记账（2026-06-15）**：上传高铁/机票/酒店截图 OCR → `parseBookingPrice` 抠出票价（认价格类字段名 + ¥/元 兜底，绝不拿车次号当价格）→ `bookingCategory` 映射（交通/住宿/其他）→ 直接 `addExpense` 记入账本。卡片显示「💰 ¥553 · 已记入账本「交通」」。未登录提示"登录后自动记账"，账本未建表给建表提示。**待优化**：记账后改价不回写、重复上传会重复记（用户可在账本删）。

### 6.3 行中手动编辑 / 导入（真实行程）
- 临场计划有变（加一站、改时间、临时订的店）→ 用户可**手动增删改行程条目**，或**导入**（如上传票务截图 OCR，见 §2 行前）。
- 数据模型已支持（Itinerary JSON 存 Supabase，可写回）；只需做编辑 UI。行程从"AI 一次性产出"变成"可生长的真实记录"。

### 6.4 飞轮如何被加固
出行次数 → **丸玩升级**；每笔消费 → **账本变厚**；行中改动 → **行程更真**。三股数据都沉淀在用户账号里，**越用粘性越强、迁移成本越高**——这就是护城河。

### 6.6 地图、交通费用、当前位置（2026-06-13 lord 提）
- **地图入口（每条景点）**：点开跳到用户选的地图 App（高德/百度/系统地图）搜索该地点。**不自建地图引擎**（瓦片/路网/路线工程量过大、不值当）。
  - 已做 MVP：deep-link 高德（`uri.amap.com/search?keyword=城市+地点`），免 key、即用。
  - 待做：让用户选地图 App（高德/百度/系统）；嵌入式地图视图。
- **交通费用估算**：相邻两点间打车/地铁/公交大概多少钱+多久。需高德等**路径规划+计价 API（要 key）**，归 Phase 2；与行中实时地图同期。
- **当前位置显示**：主页显示「你现在在 X」。已做 MVP：浏览器定位 + 免 key 反查城市（bigdatacloud）+ 手动改，存 localStorage。后续可换高德逆地理（更准、GCJ-02 对齐）。
- **配图**：行程每条的真实照片仍按 `Item.imageQuery` 走图库/POI（见 §[04 §6](04-architecture-and-data-model.md)）。

### 6.6b 记忆地图（③ 模块，先不做，记住结构）
两层叠加（2026-06-13 lord 明确）：
- **个人层**：「我解锁的地区板块」——我真正去过的省/市点亮、解锁（养成感、我的痕迹）。
- **社交层**：每个地区板块上浮现「**去过的人**」——其他用户的**头像气泡**（去过这块的人聚在这），形成社交与网络效应。
- 与丸玩成长、真实出行打卡咬合：去过 → 点亮我的板块 + 我的头像进入该板块的气泡群。
- 归 Phase 2（个人解锁）→ Phase 3（社交气泡）。先不做，结构记住。

**打卡 / 评价 / 星级（2026-06-13 lord 提）**：
- **每个景点条目可点「已打卡」**，可**附照片、也可不附**。打卡 = 真实出行确认 → 驱动丸玩成长 + 点亮记忆地图 + 我的头像进入该地区气泡。
- **开放对景点的评价 + 星级**（用户自己的点评/打分）。
- 这些打卡/照片/评价/星级**沉淀为 UGC**，喂养未来的「**景点大地图**」（别人能看到某景点的真实评价与人气）——社交与护城河数据。
- 数据：新表（如 `checkins`：user_id, itinerary_id, item/景点名, photos[], rating, review, lat/lng, created_at）。归 Phase 2（个人打卡/评价）→ Phase 3（公开到大地图）。
- **已做（2026-06-13）**：打卡 + 5 星评分 + 评论 + 照片均落 Supabase。评论存 `checkins.review`；照片上传 **Storage 桶 `checkin-photos`**（`supabase/storage.sql` 建桶+RLS），URL 存 `checkins.photos[]`。打卡累计次数 + 称号已上（`countCheckins` / `growth.ts`）。**前置**：lord 需在 Supabase 跑 `schema.sql`(checkins) + `storage.sql`(建桶)。

**帖子 / 论坛（社区 feed）—— 明确延后（2026-06-13 lord 拍板）**：
- 现在**先不做**。原因：用户基数 0 → 内容为空；涉及内容审核/举报/隐私，是独立工程。先把"自己用得爽"（行程+账本+打卡+养成）打磨好，等真实出行数据沉淀，帖子/景点大地图才有内容可填。归 **Phase 3**。

### 6.8 行前准备 / 注意事项（2026-06-15 lord 提）
- 管家不止"去哪玩"，还要给**行前要准备啥、到了要注意啥**——这才是"管家 > 攻略"。尤其**跨境/跨制式**（大陆→香港/澳门/台湾/国外）的坑：货币换汇、插头电压（如香港英标 Type G）、网络流量（大陆套餐到境外按漫游/未必通，需境外流量包/当地卡/eSIM）、证件签注（港澳通行证+签注、护照+签证）、支付方式（能否支付宝/微信、要不要现金、八达通等）。
- **已做（2026-06-15）**：行程数据加 top-level `prep: PrepNote[]`（`{category,title,detail}`，11 类）；管家 prompt 默认"中国大陆出发"判断是否跨境、必给 2~6 条 prep；`ResultView` 开场白下渲染「行前准备 · 注意事项」可折叠卡片（分类 emoji + 朱砂"嘱"印）。修改行程(revise)同 prompt 会一并保留/更新 prep。
- **飞轮关联**：哪些提醒最有用、用户实际踩了哪些坑，将来可从真实出行反馈学出来，越攒越准（见 [[data-flywheel-principle]] 思路）。
- **待做**：用户标记"已备/不适用"；按真实反馈沉淀目的地常见坑库。
- **天气（2026-06-15）**：每天日期旁显示**真实天气预报**（icon+天气+最低~最高温+易雨标记），数据来自 **Open-Meteo**（免费免 key，`src/lib/weather.ts`：城市→经纬度→按日期区间拉每日预报）。**绝不让模型编天气**（编造=假数据）。预报窗口约未来 16 天，超出的远期日期拿不到则不显示（靠 prep 的"天气穿衣"给季节性建议兜底）。

### 6.9 特殊景观 · 可遇不可求（2026-06-15 lord 提）
- 管家提醒"那几天可能撞见的特殊天象/景观"：日落火烧云、流星雨、蓝眼泪、银河星空等。这是"惊喜感/陪伴感"，通用 AI 不会主动给。
- **诚实分层（硬原则，呼应 [[data-flywheel-principle]] 的实体接地）**：
  - **可信层（天文事实/实测）**：日落日出时刻（Open-Meteo daily sunrise/sunset）、月相明暗（朔望月算法，无需 API）、流星雨极大期（静态日历按月-日匹配）、天气通透度（weather_code）。
  - **概率层（无公开 API，明确标"概率/可能、不打包票"）**：蓝眼泪（地点关键词如平潭/霞浦/福建 + 4~6月季节 + 月暗）、银河（沙漠/敦煌/茶卡等暗天地点 + 3~10月银河季 + 月暗 + 天晴）。
- 实现：`src/lib/phenomena.ts`（月相/流星雨日历/蓝眼泪/银河/日落）+ `weather.ts` 增 sunrise/sunset/clear；`ResultView` 渲染「特殊景观 · 可遇不可求」卡片（青"遇"印，每条带概率徽章：概率较高/有机会/概率较低；info 类如日落不标概率）。
- **飞轮关联**：哪些景观值得提醒、实际撞见率，可由真实打卡反馈校准（如蓝眼泪用户打卡 → 反推当晚条件，越攒越准）。
- **待优化**：流星雨日历可扩充活跃窗口（非仅极大±2天）；蓝眼泪接当地实时播报源；银河加银心高度/最佳时段计算。
