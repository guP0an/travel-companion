# 03 · 用户画像 · 用户故事 · 用户流程

> 状态：草稿 · 2026-06-13

---

## 1. 用户画像（Persona）

### 主画像：小悠（懒得做攻略的自由行青年）
- 25–35 岁，城市白领，一年出游 2–4 次。
- **痛点**：想自由行不想跟团，但做攻略太累——查景点、排路线、看哪个不绕路，光想想就放弃，最后要么随便玩要么直接跟团。
- **心理**：怕踩坑（排队、雷店）、有点审美、希望被照顾、决策容易瘫痪。
- **一句话**：「我只想有人懂我地把行程排好，我照着走就行。」

### 次画像：第一个真实用户 = lord 谷盼盼本人
- 用自己的真实出行需求作为第一个测试用例，保证产品不脱离真实。

## 2. 用户故事（User Stories）

格式：作为<谁>，我想<做什么>，以便<获得什么价值>。

**核心故事（MVP 必做）**
- US-1：作为一个懒得做攻略的人，我想**输入目的地+天数+我的脾气**，以便不用自己查就能拿到行程。
- US-2：作为怕踩坑的人，我想行程里**带贴心提醒**（哪家店几点去不排队），以便少走弯路。
- US-3：作为有审美的人，我想看到**好看、温暖**的界面，以便用着舒服、愿意分享。
- US-4：作为会反复用的人，我想**保存历史行程**，以便下次还能看。
- US-5：作为想安利朋友的人，我想**一键复制/分享行程**，以便发给同行的人。

**暂不做（记录，防遗忘）**
- US-X1：登录同步多设备（v0.1 不做，用 localStorage）。
- US-X2：实时机票酒店天气（先给建议，不接 API）。
- US-X3：付费会员（第 0 级免费）。

## 3. 用户旅程地图（情绪曲线 → 我们插针的位置）

| 阶段 | 用户在做什么 | 情绪 | 现有方案的问题 | 我们的机会 |
|------|--------------|------|----------------|------------|
| 萌生 | 「好想出去玩」 | 兴奋 ↑ | — | 接住这股兴奋 |
| 做攻略 | 查景点/看游记/排路线 | 焦虑/疲惫 ↓↓ | **最痛**：累、乱、瘫痪 | **核心切入点**：一键替他排好 |
| 决策 | 定不下来 | 烦躁 ↓ | 选择过载 | 给「带态度的建议」帮他下决定 |
| 出行 | 照行程走 | 期待 ↑ | 临场变化无人管 | 贴心提醒（先做静态，后期可动态） |
| 回来 | 想再用/安利 | 满足 | 没复用入口 | 历史保存 + 一键分享 |

**结论**：我们把全部火力压在「做攻略」这个最痛的谷底。

## 4. 用户流程图（User Flow · v0.1）

```
┌─────────────┐
│  打开网页    │
│ (首页/输入页) │
└──────┬──────┘
       │ 填写：目的地 / 天数 / 预算 / 脾气
       ▼
┌─────────────┐      点「生成行程」
│  点击生成    │ ───────────────┐
└─────────────┘                │
       ▼                        ▼
┌─────────────┐         ┌──────────────┐
│  加载中…     │         │ serverless代理│→ DeepSeek API
│ (温柔文案)   │         │ (藏Key, 生成) │←  返回行程JSON
└──────┬──────┘         └──────────────┘
       ▼
┌─────────────────────────────┐
│  结果页：带性格的每日行程      │
│  · 管家开场白                 │
│  · Day1..N (上午/下午/晚上)   │
│  · 贴心提醒                   │
│  [一键复制] [保存到本地]      │
└──────┬───────────────┬──────┘
       │保存            │返回
       ▼                ▼
┌─────────────┐   ┌─────────────┐
│  历史列表    │   │  回首页重排  │
│ (localStorage)│   └─────────────┘
└─────────────┘
```

**异常流**：
- AI 生成失败/超时 → 温柔的报错文案 + 「再试一次」按钮（不暴露技术错误）。
- 输入不全（缺目的地/天数）→ 友好提示，不让用户卡住。

## 5. 这份文档怎么用

- 开发时，每个功能对照「用户故事」编号，确保不做无关的事。
- 设计原型时，严格按「用户流程图」画页面，不拍脑袋加页面。
